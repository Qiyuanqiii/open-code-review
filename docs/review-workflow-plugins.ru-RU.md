# Плагины рабочих процессов ревью (Review Workflow Plugins)

О взаимосвязи между установкой пакетов, правами на выполнение и адаптерами среды выполнения см. в [Руководстве по архитектуре нативных плагинов](plugin-architecture.md).

Используйте рабочий процесс (workflow), когда для код-ревью требуется строгая последовательность этапов и специфические критерии завершения: например, сначала выполнить первичную инспекцию диффа, а на следующем этапе перепроверить каждое найденное замечание перед формированием итогового отчета. Пакет плагина объявляет эти этапы и валидирует результаты работы модели; OCR предоставляет дифф, правила, инструменты и бюджет токенов.

## Запуск примера single-pass

В среде, где доступен Python 3 как `python`, установите пример и выполните предварительный просмотр ревью для изменений в рабочей копии:

```sh
ocr plugin install ./examples/ocr-plugins/single-pass
ocr review --review-plugin single-pass --preview
```

При настроенном провайдере моделей и наличии изменений для проверки выполните:

```sh
ocr review --review-plugin single-pass --format json --output review.json
```

Этот пример состоит из одного этапа. Он запрашивает у модели найденные замечания и валидирует их до того, как OCR опубликует комментарии. Поле `review_plugin` в `review.json` содержит статус завершения и отчет. Сама установка не выполняет код пакета, а режим предварительного просмотра (`--preview`) не запускает Python и не отправляет запросы к модели.

Если в репозитории объявлены плагины проекта, добавьте пример в декларацию проекта и авторизуйте его согласно инструкциям ниже.

## Выбор и выполнение на уровне проекта

Для рабочего процесса, управляемого на уровне репозитория, объявите его с помощью `ocr plugin add <source>`, зафиксируйте `.opencodereview/plugins.json` и `plugins.lock.json`, затем установите через `ocr plugin sync --frozen`. Проверьте зафиксированный пакет и выполните `ocr plugin trust` для предоставления локального доверия перед вызовом `--review-plugin <id>`. Команда `ocr plugin preflight --json` проверяет целостность установленного содержимого, совместимость и статус доверия без запуска процесса и вызова модели. Если объявлены плагины проекта, выбор ограничен только зафиксированными пакетами проекта. Подробнее см. в [Руководстве по нативным плагинам OCR](native-plugins.ru-RU.md#подкоманды-управления-плагинами-проекта).

Плагин рабочего процесса управляет планом этапов, промптами, схемой завершения, валидацией и состоянием между этапами. OCR отвечает за дифф, правила, запуск модели и инструментов, сессии, учет токенов, публикацию комментариев и вывод.

Выбор рабочего процесса для одного запуска:

```sh
ocr review --review-plugin PACKAGE_ID --preview
ocr review --review-plugin PACKAGE_ID --format json --output review.json
```

Установка или включение плагина не активирует его рабочий процесс автоматически. Флаг `--preview` только считывает манифест без запуска процессов. При реальном запуске исполняемый файл плагина работает с локальными правами пользователя (аналогично локальному серверу MCP). При явном указании `--review-plugin` правила и MCP-серверы этого плагина подключаются к текущему запуску, даже если плагин глобально отключен.

## Конфигурация манифеста (Manifest)

```json
{
  "schema_version": 1,
  "id": "example-review",
  "name": "Example Review",
  "version": "1.0.0",
  "review": {
    "protocol": "stdio-v1",
    "command": "${plugin_dir}/bin/${os}-${arch}/reviewer${exe}",
    "args": ["--policy", "${plugin_dir}/policy.md"],
    "stages": ["inspect", "verify"]
  }
}
```

Поле `command` указывает путь к исполняемому файлу (запускается без оболочки shell). В командах и аргументах подставляются `${plugin_dir}`, `${os}`, `${arch}`, `${exe}` (`.exe` для Windows, пустая строка для Unix). Исполняемые среды из PATH (например, `python`) также поддерживаются. Пример на Python ожидает команду `python`. Если в системе доступен только `python3`, укажите `python3` в манифесте перед упаковкой.

Плагины могут объединять рабочие процессы, правила и инструменты MCP. Идентификаторы этапов уникальны; манифест может объявлять от 1 до 64 последовательных этапов.

## Протокол stdio-v1

OCR запускает один процесс на группу файлов с рабочей директорией в корне репозитория. Процесс сохраняет состояние на протяжении всех этапов этой группы. Запросы и ответы представляют собой однострочные объекты UTF-8 JSON (до 4 МиБ). Каждый ответ содержит `"version": 1`, а отладочная информация направляется в stderr.

### Начало этапа (`begin`)

Перед каждым этапом OCR отправляет:

```json
{"version":1,"method":"begin","stage":"inspect","paths":["main.go"],"severities":["critical","high","medium","low"],"categories":["bug","security","performance","maintainability","test","style","documentation","other"]}
```

Плагин возвращает описание задачи и опциональный начальный отчет:

```json
{"version":1,"task":{"instructions":"Inspect the selected code.","input":"Check the public return contract.","completion":{"description":"Submit the result.","parameters":{"type":"object","properties":{"checked":{"type":"boolean"}},"required":["checked"]}}},"report":{"pending":["inspection"]}}
```

### Отправка результатов моделью (`submit`)

Когда модель вызывает `task_done`, OCR пересылает аргументы без изменений:

```json
{"version":1,"method":"submit","stage":"inspect","arguments":{"checked":true}}
```

Ответ с принятием результатов должен содержать явные булевы флаги `accepted` и `complete`:

```json
{"version":1,"accepted":true,"complete":true,"report":{"checked":true},"comments":[]}
```

Если результат модели содержит исправимую ошибку, плагин возвращает `accepted:false`, непустой `feedback`, актуальный `report` и пустой массив comments. OCR передает обратную связь модели в рамках оставшегося бюджета запросов.

## Завершение и вывод результатов

Все объявленные этапы должны быть завершены. Неиспользованный бюджет токенов переносится на последующие этапы.

Массив `review_plugin` в JSON содержит статус завершения и отчеты по каждому этапу. После выполнения отчеты можно проверить с помощью `ocr session show SESSION_ID --json`. Незавершенные обязательные этапы приводят к ненулевому коду завершения CLI.
